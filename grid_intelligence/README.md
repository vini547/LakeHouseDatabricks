## Setup — Grid Intelligence

Pré-requisitos: Databricks CLI instalada e autenticada no perfil `grid_intelligence`
(`databricks auth profiles`).

1. **Crie os catálogos por SQL** (o bundle não cria catálogo — é recurso de conta):

   ```bash
   databricks experimental aitools tools query --profile grid_intelligence \
     "CREATE CATALOG IF NOT EXISTS grid_dev COMMENT 'Catalogo de desenvolvimento da Grid Intelligence'"

   databricks experimental aitools tools query --profile grid_intelligence \
     "CREATE CATALOG IF NOT EXISTS grid_intelligence COMMENT 'Catalogo de producao da Grid Intelligence'"
   ```

2. **Conceda permissão** nos dois catálogos (troque pelo seu e-mail):

   ```bash
   databricks grants update CATALOG grid_dev \
     --json '{"changes":[{"principal":"SEU-EMAIL","add":["ALL_PRIVILEGES"]}]}' \
     --profile grid_intelligence

   databricks grants update CATALOG grid_intelligence \
     --json '{"changes":[{"principal":"SEU-EMAIL","add":["ALL_PRIVILEGES"]}]}' \
     --profile grid_intelligence
   ```

3. **Valide e publique o bundle em dev**:

   ```bash
   databricks bundle validate --profile grid_intelligence
   databricks bundle deploy -t dev --profile grid_intelligence
   ```

   O deploy cria os schemas `raw`, `bronze`, `silver` e `gold` e o volume managed
   `raw.landing` no catálogo de dev. Os schemas mantêm os nomes exatos — o isolamento
   entre ambientes é feito pelo catálogo, nunca por prefixo no nome do schema.

4. **Suba os arquivos de dados** (uma pasta por base, um arquivo Parquet dentro):

   ```bash
   databricks fs cp -r <PASTA_LOCAL> dbfs:/Volumes/grid_dev/raw/landing \
     --overwrite --profile grid_intelligence
   ```

   (`<PASTA_LOCAL>` é a pasta `landing/` da sua máquina, com as quatro subpastas
   `unidades_consumidoras/`, `interrupcoes/`, `consumo_diario/` e `chamados/`.)

### Recomeçar do zero — comando DESTRUTIVO

> ⚠️ **DESTRUTIVO — não tem confirmação.** `CASCADE` remove o catálogo e **tudo** dentro dele:
> schemas, tabelas, volumes e os arquivos de dados no volume. Só rode se tiver certeza de que
> quer recomeçar do zero.

```bash
databricks experimental aitools tools query --profile grid_intelligence \
  "DROP CATALOG IF EXISTS grid_dev CASCADE"
```

# Using this project using the CLI

The Databricks workspace and IDE extensions provide a graphical interface for working
with this project. It's also possible to interact with it directly using the CLI:

1. Authenticate to your Databricks workspace, if you have not done so already:
    ```
    $ databricks configure
    ```

2. To deploy a development copy of this project, type:
    ```
    $ databricks bundle deploy --target dev
    ```
    (Note that "dev" is the default target, so the `--target` parameter
    is optional here.)

    This deploys everything that's defined for this project.

3. Similarly, to deploy a production copy, type:
   ```
   $ databricks bundle deploy --target prod
   ```

4. To run a job or pipeline, use the "run" command:
   ```
   $ databricks bundle run
   ```

5. Finally, to run tests locally, use `pytest`:
   ```
   $ uv run pytest
   ```
